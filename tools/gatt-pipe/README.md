# gatt-pipe

Chunked transfers over a pair of BLE GATT characteristics, for messages a single
characteristic value cannot carry.

The protocol is [`tools/gatt-gen/SPEC.md`](../gatt-gen/SPEC.md) §7: a chunk is
`| seq | flags | [total_len] | payload | crc16 |`, a transfer is one message, and
the two ends acknowledge each other because notifications are not acknowledged by
the link.

This crate is the state machines and the frame, and nothing else: no buffers, no
clock, no BLE, no embassy, so a host can drive both ends against each other over a
link that loses, duplicates, corrupts and stalls chunks (`cargo test`). What the
schema knows — which characteristic carries which direction, how big a chunk and a
message may be, how to encode a message — is generated by `gatt-gen`'s
`rust-trouble` target; see `tools/gatt-gen/examples/pipe` for the two together.
